# 문서 파일 입력

POST /v1/chat/completions의 messages.content 배열에 text와 file part를 함께 넣습니다.
파일은 게이트웨이에서 별도 프로세스로 해석하며, 외부 제공자에게는 검사·가명 처리를 마친 글자만 보냅니다.
파일명, 파일 바이너리, 파일 ID, 외부 파일 URL은 제공자에게 전달하지 않습니다.

## 요청

    {
      "messages": [{
        "role": "user",
        "content": [
          {"type": "text", "text": "첨부 내용을 정리해 주세요."},
          {"type": "file", "file": {
            "filename": "sample.txt",
            "file_data": "data:text/plain;base64,aGVsbG8="
          }}
        ]
      }]
    }

file에는 filename과 file_data만 허용합니다. file_data는 미디어 형식과 base64 표시가 있는 인라인 data URI입니다.
file_id, URL, 서버 파일 경로, 중복 키, 잘못된 padding과 남는 비트는 거절합니다.
파일명은 확장자 힌트를 얻는 데만 사용하고 원래 이름은 보관하거나 전송하지 않습니다.
미디어 형식만 믿지 않고 파일 바이트와 내부 구조를 확인합니다.

지원 형식은 txt·csv·md·htm·hwpx·docx·xlsx·pptx·hwp 5.0·HWPML·ZIP입니다.
PDF 글자 층은 고정 PDFium 묶음으로 빌드한 경우에만 지원합니다.
스캔본, 암호·DRM 문서, 손상된 파일, 옛 doc·xls·ppt는 거절합니다.
LaTeX·Typst의 본격적인 표기 변환과 그림의 글자 인식은 이 단계에 포함하지 않습니다.

## 검사와 예산

- 일반 텍스트만 있는 요청은 기존 HTTP 64KiB 규칙을 유지합니다.
- 파일 요청 JSON은 44MiB까지 받으며, 모든 첨부의 디코딩된 파일 합은 32MiB, 조립된 추출 글자 합은 8MiB입니다.
- 파일 part는 요청 전체에서 최대 64개입니다. 작은 파일을 많이 넣어 추출 프로세스를 과도하게 실행하는 것을 제한합니다.
- 큰 요청의 준비 단계는 동시에 2개까지 실행합니다. chunked 전송도 같은 예산을 사용합니다.
- 추출 자식은 메모리 1GiB·CPU와 벽시계 30초 등 기존 제한을 적용합니다.
- 요청 처리 단계는 기존 150초 제한을 유지합니다. 시간 안에 검사를 끝내지 못하면 외부에 보내지 않습니다.
- 문서를 줄·문단 단위로 조립하고 전체를 검사합니다. 서로 다른 문서는 구분하고 표·양식 칸 사이에는 구분자를 남깁니다.
- 장문도 모델 입력 창을 나눠 끝까지 검사하고 같은 방식으로 잔여 검사합니다. 검사하지 않은 뒤쪽을 보내지 않습니다.

모델 컨텍스트 확인을 위한 별도 왕복 호출은 하지 않습니다.
검증된 전체 요청을 보내고 제공자가 컨텍스트 초과를 명확한 기계 판독 코드로 반환하면 model_context_exceeded로 안내합니다.
사유를 명확히 구분할 수 없는 제공자 오류는 일반 provider_error입니다. 오류 원문을 노출하거나 문서를 자동으로 잘라 재전송하지 않습니다.
컨텍스트 이내의 문서라도 로컬 자원·시간·개체 수 방어에 걸릴 수 있습니다.

## 응답과 감사

파일을 처리한 성공 응답에는 기존 choices 등의 필드와 함께 prompt_airlock.documents가 추가됩니다.
각 항목에는 index, bytes, sha256, format, pages, characters, omitted가 있습니다.
pages는 실제로 알 수 없는 경우 null입니다. characters는 추출 덩어리의 글자 수이며 조립 구분자는 제외합니다.
omitted는 comments, revisions, hidden, other_parts로 나뉩니다.
other_parts는 비본문·미디어 부품 수이며 화면에서 보이는 그림 개수와 일치하지 않을 수 있습니다.

파일 정보는 외부 호출 전에 로컬 감사에 기록합니다. 본문, 원래 파일명, 시트명, 내부 위치 표는 감사와 응답에 넣지 않습니다.
파일 하나라도 읽지 못하거나 필요한 검사·감사가 실패하면 요청 전체를 거절합니다.
입력·추출·보호 단계 실패는 외부 호출 0입니다. 제공자 호출 뒤 발생한 응답·감사 실패는 이미 발생한 호출을 취소한 것으로 기록하지 않습니다.

| 오류 코드 | HTTP | 의미 |
|---|---:|---|
| body_too_large | 413 | 수신·디코딩·추출 방어 예산 초과 |
| document_invalid | 400 | 손상 등으로 읽을 수 없음 |
| document_unsupported | 415 | 지원하지 않는 형식 또는 PDF 기능 없는 빌드 |
| document_encrypted | 422 | 암호 해제 필요 |
| document_no_text | 422 | 읽을 수 있는 글자 없음 |
| overloaded | 503 | 큰 요청 준비 또는 기존 처리 예산 포화 |
| unavailable | 503 | 추출 실행기나 필요한 보호 구성 요소 사용 불가 |
| timeout | 504 | 처리 시간 제한 |
| model_context_exceeded | 400 | 제공자가 명시한 컨텍스트 초과 |

추출 실행 파일은 게이트웨이와 같은 폴더의 prompt-airlock-extract입니다.
운영체제에 따라 실행 파일 확장자가 붙습니다. 요청 본문으로 실행 파일 경로를 바꿀 수 없습니다.
내부 프로토콜 버전은 2이며 구버전 자식의 출력은 거절합니다.

설계 근거는 [ADR 0028](adr/0028-document-input.md)에 있습니다.
