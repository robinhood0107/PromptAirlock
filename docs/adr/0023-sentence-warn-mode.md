# 0023. 문장 판별기 경고 모드

상태: 확정 (2026-11-01), 채택 여부는 봉인 판정(Phase 7.9)에서 다시 정함

## 결정

학습한 문장 판별기를 Gateway 에 넣되, 판별기만 걸린 요청은 막지 않고 사용자에게 한 번 확인받는다. 규칙(ADR 0016)에 걸린 요청은 지금처럼 막는다.

| 경우 | 동작 |
|---|---|
| 규칙에 걸림 | 400 차단(지금과 같음). 판별기는 돌리지 않는다 |
| 판별기만 걸림, 확인 표지 없음 | 409 `confirmation_required`, 걸린 범주 이름과 확인 표지. provider 호출 0 |
| 같은 본문 + 맞는 확인 표지 | 통과. 감사 기록에 범주와 확인 여부 |
| 판별 실패(오류, 동시 판별 포화, 시간 초과) | 탐지 실패로 거절(`detector_unavailable` 등). provider 호출 0 |
| 설정 `sentence_warn` 을 켰는데 모델을 불러오지 못함 | 기동하지 않는다 |

판별기

- 구성: KcELECTRA-base 를 합성 반사실 셋과 정답 붙인 실제 말뭉치로 미세조정, seed 1, 문턱값 alpha 0.03(#185, #187).
- 판정: 글을 문장으로 나눠 문장마다 범주 12칸(범주 11 + 없음) 확률을 내고, 없음을 뺀 가장 큰 범주 확률이 그 범주 문턱값 이상이고 개인 조건 v2(NER 사람, 개인 표지, 소유 표현 x 친족어, 가리키는 말 x 사람 명사, 3인칭 대명사)가 있으면 걸린다. 인증 정보 범주는 개인 조건 없이 쓴다.
- 메시지 segment 마다 판별한다. stop 문자열은 판별하지 않는다.
- 모델 파일은 저장소 밖에 두고 `classifier.json` 의 SHA-256 을 코드에 고정한다. 이 파일이 모델과 tokenizer 해시, 범주 순서, 문턱값, 개인 조건 목록을 담는다.
- 실행: ONNX Runtime CPU, 세션 하나를 동시 판별 2개가 함께 쓰고, 판별 하나에 계산 스레드 2개.

확인 표지

- 128 bit 난수(16진수 32자). 받은 본문 바이트의 SHA-256 에 묶는다. 본문이 한 byte 라도 다르면 쓸 수 없다.
- 한 번 쓰면 맞든 틀리든 지운다. 5분이 지나면 쓸 수 없다. 메모리에만 두고 재기동하면 사라진다.
- 살아 있는 표지는 1,024개까지. 다 차면 새 표지를 주지 않고 503 `overloaded` 로 거절한다.
- 요청 헤더 `X-Prompt-Airlock-Confirm` 로 받는다. 두 개 이상이거나 32자를 넘으면 400.

응답과 기록

- 409 응답에는 범주 이름과 확인 표지만 담는다. 문장, 위치, 점수는 담지 않는다(우회 탐색 방지, ADR 0016 과 같은 이유).
- 감사 기록 `sentence_warn` 에는 범주 이름과 확인 여부만 남긴다. 확인 뒤 보낸 요청의 외부 전송 이력은 다른 통과 요청과 같다(ADR 0021).

## 수치(#188)

| 항목 | 기준 | 결과 |
|---|---|---|
| C++ 와 학습 모델(float32) 확률 차이 | 1e-4 이하 | 최대 1.27e-05, 판정 다른 글 0 / 16,842 |
| 256 token 판별 p95 | 150 ms 이하 | 127.304 ms(스레드 2) |
| 메모리 증가 | 700 MB 이하 | 실행 중 +540.7 MB, 불러오는 순간 최대 +1,165 MB |
| 실제 test 재현율 / 정상 경고 | 참고 | 69.7% / 3.2% |
| dev3 재는 쪽 돌려 말함 재현율 / 정상 경고 | 참고 | 80.3% / 0.0% |

## 근거

- 학습 없이 쓴 판별기는 판정용 셋에서 사람 이름이 든 정상 업무 문장의 27.3% 를 잘못 막았다(ADR 0022). 처음 보는 문장 모양에서 흔들릴 수 있다는 뜻이다. 막으면 사용자가 우회 표현을 찾게 되므로, 한 번 멈춰 확인받는 쪽이 차단보다 덜 해롭다(결정 #166).
- 판별하지 못한 요청을 그대로 보내면 판별기가 꺼진 것과 같으므로 막는다(실패하면 막는 쪽, fail closed).
- 표지를 본문 해시에 묶고 한 번만 쓰게 해, 확인받은 표지로 다른 내용을 보내거나 같은 표지를 되풀이해 쓰지 못하게 한다.

## 대안

| 대안 | 거절 이유 |
|---|---|
| 판별기만 걸려도 차단 | 실제 test 정상 경고 3.2% 를 그대로 차단하면 업무 문장 서른 개 중 하나를 막는다. 차단 승격은 실제 문서 판정 뒤에 따로 정한다 |
| 경고만 하고 그대로 보냄 | 사용자가 보기 전에 나가 버려 경고의 뜻이 없다 |
| 본문에 확인 필드를 넣음 | 본문을 다시 정규화해 해시를 내야 해서 묶는 대상이 흐려진다. 헤더는 본문 바이트를 그대로 묶는다 |
| 서명한 표지(서버 상태 없음) | 한 번만 쓰기를 지키려면 결국 쓴 표지 목록이 필요하다 |

## 남은 것

- 봉인 판정 셋과 실제 기관 문서로 경고 모드를 채택할지 정한다(Phase 7.9).
- 앞선 대화의 메시지도 매번 다시 판별하므로, 한 번 확인한 내용이 다음 요청에서 다시 걸릴 수 있다. 실제 운영 기록을 보고 줄일지 정한다.
- 불러오는 순간의 메모리 최대치(+1,165 MB)는 모델 바이트와 ONNX Runtime 사본이 잠깐 함께 있어서다. 배포 묶음(Phase 13)에서 다시 본다.
