# 0006. 한국어 NER과 tokenizer

상태: 확정 (2026-10-05)

## 결정

- 모델: Hugging Face `atonlee/koelectra-ko-pii-ner`, 커밋 1e75c01e707232401883cf364151bbe2e560c708의 `onnx/model.onnx`(fp32, 53.9 MiB, Apache-2.0).
- 모델 라벨 중 사람 이름과 조직만 쓴다. 전화번호, 주민등록번호 같은 형식 있는 값은 결정론 detector가 맡는다.
- tokenizer: 모델과 같은 커밋의 `tokenizer.json`을 직접 읽는 C++ WordPiece 구현. 지원하지 않는 구성이면 로드를 거부한다.
- 입력이 512 token을 넘으면 자르지 않고 오류로 거부한다. 긴 입력 분할은 NER 통합 단계에서 다룬다.
- 이름 끝 음절과 조사가 한 subword로 묶이는 경우는 받침 호응을 확인하는 후처리로 경계를 자른다.
- 긴 입력은 문장 경계에서 256 token 이하 창으로 나눠 추론한다(Phase 7). 모델이 낸 구간은 어절 단위로 넓힌 뒤 정답 규칙에 맞춰 다듬고, 모델이 놓친 기관명은 결정론 규칙으로 보탠다(아래 "Phase 7 재측정").

합격 기준(합성 fixture 기준)

| 항목 | 기준 |
|---|---|
| offset 오류 | 0 |
| PERSON recall(정확 일치) | 0.9 이상 |
| ORGANIZATION recall(정확 일치) | 0.8 이상 |
| 256 token, CPU 1 thread p95 | 200 ms 이하(정규화, tokenize, 추론, decode 전체) |

정확 일치는 탐지 구간의 시작과 끝이 정답 구간과 모두 같을 때만 맞힌 것으로 센다. 정답 구간에는 호칭, 직함, 조사, 서술격 조사, 법인 표기((주), 주식회사 등), 부서명을 넣지 않는다. 이름 전체가 가려졌는지(덮임)는 참고값으로 함께 기록한다(2026-10-21 결정 #107).

## 대안

| 후보 | 결과 |
|---|---|
| 같은 모델 int8(14 MiB) | 기준 통과, ORG recall 0.818로 여유 없음 |
| `1T/veil-pii-ko-lite` int8 | 256 token p95 310.7 ms로 지연 기준 미달 |
| `Wismut/nym-pii-multilingual-small` int8 | ORG recall 0.364로 미달 |
| GLiNER multi v2.1 | 미측정 |
| `1T/veil-pii-ko-lite` int8(Phase 7 재검토) | 최종 판정용 셋에서 가려지지 않은 이름 8 / 600(지금 모델 13), 256 token p95 298 ms 로 지연 기준 미달, 잔여 검사 거절 153 / 4,500 |
| 지금 모델 + `tasoo/ko-pii-detector-ax-tokenclf-onnx` 사람 보조(Phase 7 재검토) | 가려지지 않은 이름 10 / 600, 오탐 85(지금 모델 57), p95 291 ms, 메모리 1.6 GB |

라이선스 표기가 없거나 비상업 조건이거나 ShareAlike 조건인 후보, ORG 라벨이 없는 후보, ONNX 배포본이 없는 후보는 측정하지 않았다.

## Phase 7 재측정(2026-10-21)

합성 셋(각 900문장: 사람 300, 기관 300, 이름 없는 문장 300)을 고정 seed 생성기로 만들었다. 개발용 셋으로 경계 후처리와 결정론 기관 규칙을 다듬고, 결과를 본 판정용 셋은 참고값으로 돌린 뒤 규칙을 고정하고 새로 만든 최종 판정용 셋으로만 합격을 판정했다. 측정 도구는 `tests/measure/ner_measure.cpp`, 셋은 `tests/fixtures/ner/`.

| 항목 | 최종 판정용 셋 | 기준 |
|---|---|---|
| offset 오류 | 0 | 0 |
| PERSON recall(정확 일치, NER) | 0.973 | 0.9 이상 |
| ORGANIZATION recall(정확 일치, NER) | 0.910 | 0.8 이상 |
| 256 token p95(Windows / WSL) | 28.2 / 26.3 ms | 200 ms 이하 |
| 정답 이름이 가려지지 않은 수(탐지기 전체) | 17 / 600 | - |

- 탐지기 전체는 NER 에 결정론 기관 규칙(앞말 + 회사명 꼬리, 법인 표기 뒤 어절)을 더한 것이다. 사람·기관 이름이 가려진 비율은 0.973 / 0.970 이었다.
- 최종 판정에서 이름 끝 '랑'(하랑)을 조사로 잘라 내는 버그가 드러나(잔여 검사 거절 10 / 4,500) 판정 뒤 고쳤다. 고친 뒤 같은 셋에서 PERSON 0.987, 가려지지 않은 수 13 / 600, 잔여 검사 거절 0 / 4,500 이다(참고값).
- 경계 후처리 전에는 같은 모델이 개발용 셋에서 ORGANIZATION 0.650(정확 일치)이었다. 차이는 대부분 경계(직함·법인 표기·부서명 포함, 어절 일부만 잡음, 영문 이름 뒤 조사)였다.
- 정규화: NFKC 의 정밀도가 NFC 보다 낮지 않았다. NFKC 를 유지한다(ADR 0007).
- 남은 약점: 후처리·기관 규칙의 목록에 없는 회사명 꼬리(최종 셋의 '파마', '메디칼' 등)와 모델이 놓치는 이름(두 글자 이름, 복성 일부)은 가려지지 않는다. 이름 없는 문장 300개에서 사람·기관으로 잘못 찾은 것은 57개(가려지기만 하고 새지는 않는다)다. 더 줄이려면 모델 교체를 검토한다(아래 변경 조건).

## 라이선스

- 모델 가중치는 Apache-2.0(모델 카드 표기)이며 배포 묶음에 포함할 수 있다. 배포 시 Apache-2.0 전문, 출처 저장소와 커밋, 저작자 표시를 넣는다.
- 학습 데이터 두 종(BCCard/pii-masking-openpii-finance, townboy/korean-pii-dataset)과 앞의 원천(ai4privacy/pii-masking-openpii-1.5m)은 CC BY 4.0이다. 가중치가 데이터의 2차적 저작물인지는 정리되지 않았으므로 데이터 저작자 표시를 함께 넣는다(`THIRD_PARTY_NOTICES.md`, #198).
- 기반 모델(KoELECTRA-small v3)은 Hugging Face 카드에 라이선스 표기가 없고 GitHub 저장소의 Apache-2.0에 기댄다.
- 기반 모델 사전학습에 쓰인 국립국어원 모두의 말뭉치는 약정한 사람이 결과물을 공개하기 전에 사전 승인을 받고 활용 사실을 밝히게 한다. 그 의무는 기반 모델 제작자에게 있고, 승인 여부는 공개 자료로 확인하지 못했다(#198). 고지에 활용 사실을 적고, 배포 전에 문의해 막히면 모델을 바꾼다(#102).

## 보안 영향

- 탐지하지 못한 이름은 가명화되지 않는다. 잔여 검사와 기관 보호어로 보완하지만 recall이 1이 아니므로 남는 위험이 있다. Phase 7 최종 판정용 합성 셋에서 가려지지 않은 이름은 13 / 600(약 2.2%, 기관 9·사람 4)이었다. 기관은 목록에 없는 회사명 꼬리가 대부분이라, 운영 기관이 자기 기관·계열사·거래처 이름을 기관 보호어 목록에 넣어 결정론으로 막는다.
- 받침 있는 이름이 조사와 같은 글자로 끝나면(예: 이름이 "이"로 끝남) 후처리가 이름을 잘못 자를 수 있다.
- 모델 파일은 고정 커밋과 SHA-256으로 확인한다. 실행 중에 모델을 내려받지 않는다.

## 변경 조건

- 더 큰 합성 셋에서 합격 기준에 미달하면 다른 후보로 바꾼다. Phase 7 에서 후보 5개를 다시 검토했으나 지연·메모리·잔여 검사 조건을 모두 만족하는 후보가 없어 유지했다.
- 사전학습 코퍼스 이용 조건을 확인한 결과 재배포에 문제가 있으면 바꾼다.
