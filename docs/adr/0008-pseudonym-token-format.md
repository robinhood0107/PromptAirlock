# 0008. 가명 token 형식

상태: 확정 (2026-10-05)

## 결정

형식은 `⟦<LABEL>_<R>⟧`이다.

- LABEL: entity type 이름, `[A-Z][A-Z0-9_]{0,23}`.
- R: Crockford base32 대문자 10자(50비트), CSPRNG로 만든다. I, L, O, U는 쓰지 않는다.
- 예: `⟦PERSON_7Q2MK4XD9A⟧`

규칙

- 같은 scope 안에서 같은 type, 같은 값이면 같은 token을 돌려준다. scope마다 무작위 키를 쓰는 역색인으로 찾고 저장된 원문과 정확히 비교한다.
- 다른 값은 다른 token이다. 같은 scope 안에서 중복 R은 생성 시 거절한다.
- 원문의 hash나 HMAC으로 token을 만들지 않는다.
- R에 원문의 연속 4자가 나타나면 다시 뽑는다.
- 복원은 문자열이 정확히 같을 때만 한다. 대소문자, 공백, 괄호 모양이 바뀐 token은 복원하지 않는다.

## 대안

- scope 안 순번(`⟦PERSON_1⟧`).
- 순번과 짧은 hex(`⟦PERSON_0001_A7F2⟧`).

## 근거

- 순번 형식에서는 다른 scope의 `PERSON_1`이 현재 scope의 다른 사람으로 조용히 복원될 수 있다. 무작위 R은 이 경우 TOKEN_NOT_FOUND로 실패한다.
- 순번은 등장 순서와 개수를 드러낸다.
- 다른 scope token이 우연히 일치할 확률은 mapping 4096개 기준 약 3.6e-12다.
- 변형 7종(소문자화, 공백 삽입, 괄호 제거, ASCII 괄호, 한 글자 변경, 라벨 변경 등)을 모두 복원 거부했다.

## 보안 영향

- token 문자열에서 원문 값을 얻을 수 없다. 단 문장 문맥에서 속성을 추론하는 위험은 가명화로 없어지지 않으며 따로 측정한다.

## 변경 조건

- 실제 LLM 응답에서 token이 바뀌는 비율이 높게 측정되면 형식을 다시 정한다. 바뀐 token은 복원하지 않는다는 규칙은 유지한다.
