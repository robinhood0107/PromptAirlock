# 0016. 탐지 범위: 계좌번호, 인증 정보, 민감정보, 고유식별정보

상태: 확정 (2026-10-05)

## 결정

개인정보 종류 여섯 개를 더하고 모두 차단한다. 종류는 17개가 된다.

| 종류 | 대상 |
|---|---|
| BankAccount | 국내외 은행 계좌번호 |
| Credential | 비밀번호, PIN, 인증번호, OTP 같은 인증 정보 |
| SensitivePersonalInfo | 특정 개인의 건강, 사상·신념, 노동조합·정당 가입, 정치적 견해, 성생활, 유전정보, 범죄경력, 생체인식, 인종·민족 정보 |
| KoreanPassportNo | 여권번호 |
| KoreanDriverLicenseNo | 운전면허번호 |
| KoreanAlienRegistrationNo | 외국인등록번호 |

BankAccount

- 숫자 사이의 하이픈, 공백, 점은 지우고 숫자 순서로만 본다. 같은 숫자 순서면 어떻게 끊어 써도 같은 계좌다.
- 국내 형식표: 금융기관별 계좌 체계(자릿수, 과목코드 위치와 값)에 맞으면 문맥과 상관없이 차단한다. 구조 제약이 없는 일련번호형 계좌와 휴대폰 번호형 계좌만 문맥이 있을 때 차단한다.
- 외국 구조 형식: IBAN(국가별 길이와 구조), 일본 지점-계좌 형식, 영국 sort code와 계좌, 미국 ABA routing과 계좌, 캐나다 transit과 계좌, 호주 BSB와 계좌, 인도 IFSC와 계좌, 멕시코 CLABE, 중국 은행카드 번호. 구조가 맞으면 차단한다. 검증 자리 계산이 틀려도 차단한다.
- 계좌 문맥 규칙: 계좌를 가리키는 말(계좌, 입금, 예금주, 은행 이름, account, IBAN, 口座 등)이 가까이 있으면 6~34자리 숫자열을 차단한다. 형식표에 없는 기관, 나라, 새 형식은 이 규칙으로 막는다.
- 휴대폰 번호와 사업자번호는 계좌 문맥이 없으면 원래 종류로, 있으면 계좌로 본다.

Credential

- 표지어(비밀번호, PIN, 인증번호, OTP, password, パスワード, 密码 등) 뒤의 값을 차단한다.
- URL 안의 사용자 이름과 비밀번호, 접속 문자열의 Password 값, HTTP Basic 인증 값을 차단한다.
- 계정을 가리키는 말이 가까이 있고 무작위 문자열 조건에 맞는 값을 차단한다.

SensitivePersonalInfo

- 문장 단위로 판정하고 직전 문장까지 범위를 넓힌다.
- 같은 범위에 특정 개인 표지(이름, 개인 식별 정보, 호칭, 자기 진술)와 민감정보 범주어가 함께 있으면 차단한다. 개인 표지가 없으면 일반 지식으로 보고 통과시킨다.
- 범주어가 있었으나 통과한 요청도 감사 기록에 범주와 건수를 남긴다. 값은 남기지 않는다.
- 이 방식은 단어 기반 임시 필터다. 문장 단위로 이해하는 판별기를 별도 실험으로 검증하고, 통과하면 단어 규칙과 함께 쓴다.

고유식별정보

- 여권번호, 운전면허번호는 공개된 형식으로, 외국인등록번호는 주민등록번호와 같은 구조로 판정한다.

데이터 관리

- 형식표, 문맥어, 표지어, 범주어는 소스 안의 데이터 파일로 둔다. 실행 중 내려받거나 기관 설정으로 바꾸지 않는다.
- 파일과 항목마다 출처, 확인일, 바뀌었을 때 고칠 곳을 주석으로 적는다. 항목마다 맞는 예와 비슷하지만 아닌 예를 시험한다.
- 출처는 금융결제원, SWIFT, 각국 지급결제기관, 법령 같은 공식 원천을 쓴다.

## 대안

| 대안 | 거절 이유 |
|---|---|
| 계좌번호는 문맥이 있을 때만 차단 | 국내 계좌는 하이픈 없이 숫자만 쓰는 경우가 많아 문맥 없는 계좌가 그대로 나간다 |
| 10~14자리 숫자는 모두 차단 | 형식 정보를 버리게 되고, 형식표로 줄일 수 있는 오탐까지 생긴다 |
| 민감정보 범주어가 나오면 무조건 차단 | 특정 개인과 무관한 일반 질문(질병의 증상 등)까지 막는다 |
| 민감정보를 탐지하지 않고 사용자 안내에 맡김 | 공식 문서가 시스템의 탐지·차단을 요구한다 |

## 근거

쪽은 인쇄 쪽이다.

| 확인한 내용 | 근거 |
|---|---|
| 상용 서비스 API로 업무 지원 시스템을 만드는 경우에도 이 절의 대책을 적용한다 | 국가ㆍ공공기관 보안 가이드북 p.56 |
| 기관 민감정보가 입력되지 않도록 입·출력 필터링을 한다 | 보안 가이드북 p.57(사례), M13(p.37) |
| 문장 단위로 이해하는 기능으로 민감정보 입·출력을 통제한다 | 보안 가이드북 p.58 |
| 문장을 이해하는 제품을 써야 하며, 없으면 단어 기반 필터를 임시로 쓰되 로깅·모니터링한다. 띄어쓰기, 은어, 다른 단어, 문장 조합 우회에 대비한다 | 보안 가이드북 FAQ Q5(p.93) |
| API 입력에 개인정보가 있는지 확인한다 | 2023 국가정보원 외부 언어모델 활용 보안 가이드라인 p.42 |
| 주민등록번호, 신용카드 번호, 은행 계좌 정보, 비밀번호, 민감한 개인정보(건강, 종교, 정치적 성향 등), 인증 정보(사용자 이름, 비밀번호, 인증 코드)를 입력하지 않는다 | 같은 문서 p.30 |
| 민감정보의 범위 | 개인정보 보호법 제23조 ①, 같은 법 시행령 제18조 |
| 고유식별정보의 범위(주민등록번호, 여권번호, 운전면허번호, 외국인등록번호) | 개인정보 보호법 시행령 제19조 |

- p.30은 무엇이 민감정보인지의 목록이고, p.42, p.56~58, M13, Q5는 API 기반 시스템이 그것을 탐지·차단해야 한다는 요구다. 그래서 Gateway가 p.30 목록을 차단하는 것은 시스템 요구의 직접 이행이다.
- 국내 계좌번호는 금융기관마다 7~14자리로 다르고 검증 자리 계산법이 공개돼 있지 않다. 그래서 형식표, 외국 구조 형식, 문맥 규칙의 세 겹으로 덮는다.

## 보안 영향

- 계좌형 숫자열이 들어간 업무 질의가 차단될 수 있다. 차단 사유 코드로 사용자가 그 부분을 지우고 다시 보내게 한다. 오탐률을 측정해 기록한다.
- 문맥 없는 무작위 비밀번호와 개인 표지 없는 우회 표현은 단어 규칙으로 판별할 수 없다. 문장 단위 판별기 검증 전까지 남는 위험이다.

## 변경 조건

- 금융기관 계좌 체계, IBAN 국가 목록, 법령 범위가 바뀌면 데이터 파일과 시험을 함께 고친다.
- 문장 단위 판별기가 기준을 통과하면 단어 규칙과 함께 쓰도록 이 문서를 고친다.
