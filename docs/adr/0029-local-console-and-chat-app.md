# 0029. 로컬 콘솔의 미리보기와 채팅 앱 확인

상태: 확정 (2026-11-19, #263·#270).

## 결정

- `POST /v1/preview`는 대화 요청과 같은 출처 인증·등급 확인·허용 필드·입력 상한을 적용한다.
- 미리보기는 대화 요청과 같은 탐지·정책·가명화·잔여 검사를 거친다. 검증을 마친 전송 예정 내용과 종류별 건수, 문서 처리 통계를 반환한다. 문서 제목과 원문은 통계에 넣지 않는다.
- 미리보기는 제공자를 호출하지 않고 실제 전송 이력도 쓰지 않는다. 감사 기록은 원문 없는 `preview` 메타데이터로 구분한다.
- 미리보기의 가명 범위는 응답 전에 정리한다. 이후 실제 요청은 새 범위를 쓰므로 가명 문자열이 미리보기와 다를 수 있다.
- 확인이 필요한 요청은 기존 409 응답을 사용한다. 미리보기에 확인 표지를 붙여도 승인으로 사용하거나 소모하지 않는다.
- 실패한 검사의 중간 내용은 반환하지 않는다. 시간 초과·취소·기록 실패에도 제공자 호출은 없다.

## 채팅 앱 연결

기본 409 흐름은 유지한다. `compat.chat_app`을 명시적으로 켜면 차단·확인 상태만 일반 대화 안내로 반환한다. `prompt_airlock.decision`에 판정을 명시하고, 차단을 승인으로 바꾸지 않는다. 인증·입력·제공자 오류는 기존 오류로 유지한다. 안내를 200 응답으로 바꿔도 원래 거절된 연결은 닫아 읽지 않은 본문을 다음 요청으로 해석하지 않는다.

로컬 승인 화면은 `GET /console/confirm?token=...`로 제공하고, JavaScript·CSS·아이콘도 같은 출처의 내장 파일만 사용한다. 정적 화면에는 비밀값이 없으므로 로컬 접근만 확인하며, 실제 승인은 출처 token 인증을 거친다. Host·접속 주소·Origin 제한은 승인 API와 같다. CSP로 스크립트·스타일·연결을 같은 출처로 제한하고 프레임·리퍼러 전송을 막는다. 로그인 값은 URL·브라우저 저장소·화면 응답에 넣지 않는다.

`POST /v1/confirmations/approve`는 등록된 출처의 인증과 공개 등급 확인에 더해 접속 주소·Host·Origin을 확인한다. 접속 주소는 127.0.0.1, Host는 같은 게이트웨이의 로컬 주소여야 한다. 브라우저가 보낸 Origin도 같은 출처여야 하며 중복 Host·Origin은 거절한다.

- 본문은 `{"token":"확인 표지"}` 하나이며 1 KiB를 넘지 못한다. 다른 키·중복 키·형식 오류를 거절한다. 확인 헤더와 함께 보내는 요청도 거절한다.
- 장부는 본문 SHA-256과 인증 출처만 보관한다. 원래 요청 본문을 승인 대기 상태로 저장하지 않는다.
- 감사·취소·시간 검사를 마친 뒤 승인으로 바꾼다. 이 검사와 상태 변경은 같은 잠금 안에서 실행해 다른 요청의 사용과 엇갈리지 않게 한다.
- 만료 시각은 호출자가 읽어 전달하지 않는다. 장부가 잠금을 획득한 뒤 시각을 읽고, 감사 검사 후에도 다시 확인한다. 기다리는 동안 만료된 승인은 사용할 수 없다(#271).
- 승인 직전의 `confirmation` 기록은 검사된 승인 의도와 본문 해시를 남긴다. 표지 원문은 기록하지 않는다. 기록 실패 시 승인 상태를 만들지 않는다.
- 원래 앱이 같은 본문을 다시 보내면 승인을 한 번 사용한다. 승인·미리보기는 만료 시간을 늘리지 않는다. 기존 확인 헤더와 승인된 본문 방식이 경쟁해도 한 번만 사용할 수 있다.
- 명시적인 빈 확인 헤더도 형식 오류다. 빈 헤더를 승인된 본문 방식으로 해석하지 않는다.
- 승인 API 자체는 제공자·탐지기·Vault를 호출하지 않는다. 실제 전송 요청에서는 모든 보호 단계를 다시 실행한다.

본문 바이트 SHA-256·1회 사용·5분 만료·1,024개 상한을 유지한다([0023](0023-sentence-warn-mode.md)). 차단된 요청은 확인 장부에 들어가지 않으므로 승인으로 보낼 수 없다.

## 출처별 확인 요청 목록 (2026-11-23, D3 #275)

`GET /v1/confirmations/pending`은 승인 대기자가 기존 출처 인증값으로 자기 출처의 현재 확인 장부를 읽는다. 기존 Bearer 인증과 공개(O) 등급 확인을 사용하며, 접속 주소 127.0.0.1·정확한 Host·Origin이 있으면 동일 출처를 요구한다. 중복 인증/등급/Host/Origin, 확인 표지 헤더, Content-Type, 본문, 원격 접속은 거절한다. 서버 응답은 `no-store`다. 관리자 전용 출처는 대화·미리보기·승인과 같이 이 경로도 사용할 수 없다.

조회는 ConfirmLedger 잠금 안에서 출처가 같은 미만료 항목만 snapshot으로 복사한다. 승인 대기 항목은 기존 확인 링크에 필요한 approval mark, state, 남은 초를 반환한다. 이미 승인된 항목은 state와 남은 초만 반환하고 표지와 다시 열 링크를 주지 않는다. 사용·만료 항목 및 다른 출처의 항목은 보이지 않는다. 예정 시간이 가장 가까운 항목부터 25개까지 반환하고, 더 있으면 `truncated=true`로 알린다. 조회는 승인·소모·만료 연장을 하지 않는다.

응답에는 요청 본문·본문 hash·다른 출처·인증값을 넣지 않는다. 목록 접근 감사는 기존 `confirmation` 형식에 `operation=list`로 기록해 일반 요청 수와 실제 승인 수를 늘리지 않는다. 감사 기록이 없거나 쓰기 실패이면 항목을 반환하지 않는다. 목록 읽기는 detector·Vault·provider를 호출하지 않는다.

내장 콘솔은 출처 인증값을 password 입력에서 읽어 Authorization 헤더로만 보내고 요청을 시작할 때 입력을 비운다. 승인 표지는 별도 비밀 입력으로 받지 않으며, 대기 항목에서 같은 출처의 기존 `/console/confirm?token=...` 링크를 여는 데만 쓴다. 승인됨 항목은 상태만 표시한다.

## 대안

| 대안 | 거절 이유 |
|---|---|
| 별도 경량 탐지로 미리보기 | 실제 전송의 보호 결과와 달라질 수 있다 |
| 미리보기 뒤 같은 가명 범위를 보관 | 원문 대응 상태가 요청을 넘어 살아 있게 된다 |
| 미리보기를 전송 이력으로 기록 | 실제로 보내지 않은 내용을 보냈다고 기록하게 된다 |

## 보안 영향

새 입구에서도 검증된 내용만 전송 예정 결과로 만든다. 원문 민감값·매핑·자격 증명·차단 위치는 반환하지 않는다. 미리보기 이후 실제 전송의 보안 검사를 생략하지 않는다.

## 변경 조건

앱 호환 모드와 승인 입구를 추가할 때 인증 출처·본문 묶음·재사용·만료·로컬 접근 제한을 함께 시험한다. 승인 목록은 기존 출처의 읽기 전용 화면이며 승인 자체는 기존 경로와 계약을 유지한다. 사용자 승인 #276의 감사 조회는 ADR 0031의 별도 전용 관리자 출처를 쓴다.
