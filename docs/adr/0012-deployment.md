# 0012. 배포와 운영 전제

상태: 확정 (2026-10-05)

## 결정

배포

- 대상 OS는 Windows x64와 Linux x64다.
- OS마다 배포 묶음 하나를 만든다. 묶음에는 Gateway 실행 파일, Vault 실행 파일, NER 모델과 tokenizer 파일, 런타임 라이브러리, 설정 파일 하나, 라이선스와 제3자 고지가 들어간다.
- 기관은 Gateway만 실행한다. Vault는 Gateway가 띄우고 Gateway가 끝나면 함께 끝난다.
- 기관 애플리케이션은 Chat Completions 호환 API 주소를 Gateway로 바꾸는 것으로 연동한다.
- 기관이 정하는 설정은 외부 provider 주소와 자격 증명, 허용 출처(인증 수단과 등급 정책, [0013](0013-grade-identification.md)), 기관 보호어 목록, 이력 보존 기간으로 한정한다. provider 주소는 기관 DMZ의 중계 서버나 프록시를 가리킬 수 있다.
- transport, 모델, 정규화 방식, token 형식은 설정으로 바꿀 수 없다.

운영 전제

- Gateway는 기관이 공개(O) 등급으로 분류한 업무정보만 받는다. 등급 분류는 기관 절차다. Gateway는 등급을 확인하고 내용을 검사해 잘못 분류되거나 잘못 들어온 정보를 막는다. 등급을 확인하는 방법은 [0013](0013-grade-identification.md)에 있다.
- Gateway는 외부 언어모델 연계 구간의 콘텐츠 통제를 맡는다. 우회 접속 차단, 사용자 인증 서버, 악성코드 검사, 네트워크 분리는 범위 밖이다.
- 개인정보 가명화는 O 요청에 섞인 개인정보를 줄이는 추가 방어다. 가명화했다고 민감(S) 정보가 공개(O) 정보가 되지는 않는다.
- 가명으로 바꿔 보낸 내용도 개인정보다. 외부 provider(국외 포함)로 보내는 데 필요한 처리위탁·국외 이전의 법적 근거와 절차는 기관이 갖춘다. Gateway는 그 근거를 대신하지 않는다.
- Gateway는 기관의 민감(S) 영역에 둔다. 기밀(C) 정보는 입력 대상이 아니며, C로 표시된 요청은 차단한다.
- 감사 로그는 민감(S) 정보로 취급해 로컬 파일로 기록한다. Gateway에는 로그를 외부로 보내는 기능이 없다. 기관이 민감(S) 영역 안의 로그 수집 체계로 이 파일을 가져가는 것은 허용하며, 민감(S) 영역 밖으로 반출하지 않는다.
- 감사 로그와 이력의 보존 기간은 1년 이상만 설정할 수 있다(기본값 1년). 기록은 위·변조를 확인할 수 있게 연결 해시로 남기고, 열람은 관리자만 한다.
- 프롬프트와 결과 이력은 외부로 실제 나간 그대로 보관한다. provider에 보낸 프롬프트(가명 token 상태)와 받은 응답(복원 전)을 민감(S) 영역 로컬 저장소에 기록하고, 복원된 원문은 보관하지 않는다. 보존 기간이 지나면 자동 삭제하며 열람은 관리자만 한다. 차단된 요청은 본문 없이 감사 메타데이터만 남는다. 가명을 원래 값으로 되돌린 사실(횟수와 종류, 값 제외)도 감사 메타데이터로 남긴다.
- 연결은 Gateway에서 외부 언어모델 서비스 방향으로만 연다. 외부에서 Gateway나 Vault로 들어오는 연결은 받지 않는다. 요청에 대한 응답은 같은 연결로 돌아오며, 요청과 응답은 방향별로 따로 검사한다. 이것은 물리적 일방향 전송 장치(IF-5)를 대신하지 않는다. 그런 장치를 쓰는 환경에서는 응답이 돌아올 수 없으므로 이 구성을 쓸 수 없다.
- 실제 도입에 필요한 보안성 검토는 기관 절차이며 이 소프트웨어가 대신하지 않는다.

## 대안

- 기관이 transport, 모델, 정규화를 고르는 설정 제공.
- Gateway가 요청의 정보 등급을 스스로 판정.
- 외부 로그 수집기 연동 기능 제공.
- 이력을 보관하지 않고 provider 쪽 기록에 맡기기.
- 복원된 원문까지 암호화해 보관하기.

## 근거

- 국가 망 보안체계(N2SF) 보안 가이드라인 1.0 본문은 업무정보 등급 분류를 기관이 수행하는 절차로 두고, 개인정보와 로그를 민감(S)으로 분류한다(본문 표 2-8).
- 같은 가이드라인 부록 2-2(정보서비스 모델 2)는 외부 언어모델 서비스에 쓰는 업무정보를 O등급으로 한정하고(p.11), 연계체계를 S 영역에 두며(그림 2-5), 연계체계가 등급 식별과 프롬프트·콘텐츠 필터링으로 O 외 정보 유출을 막도록 한다(p.24). 부록은 제시한 통제를 절대 기준이 아닌 검토 사항으로 둔다(p.8). 이 문서의 결정은 준수나 인증을 뜻하지 않는다.
- 같은 부록은 서비스 데이터 관리 항목으로 프롬프트와 결과 이력 관리를 두고(그림 2-9), 데이터 사용 정책에 목적, 접근 권한, 보존 기간, 폐기 절차를 담도록 한다(표 2-5). 외부로 나간 그대로 보관하면 기관 밖으로 무엇이 나갔는지를 정확히 남기면서 개인정보 원문이 한곳에 모이지 않는다.
- 같은 부록은 연계체계가 단말에서 서비스 방향의 일방향 흐름만 허용하고 외부의 비인가 접근을 막도록 하면서(p.24), 서비스가 생성한 정보를 단말로 가져오는 것은 허용한다(p.13). 부록1의 IF-5는 일방향 전송 장치로 역방향을 막는 통제이며 우선검토 대상은 기밀(C) 등급이다(p.63). 부록 2-11은 같은 연계체계를 양방향 Transfer CDS 예시로 들고 방향별 검증을 요구한다(p.14, p.37~41). 그래서 연결 방향 제한(EB-3, IF-9, IF-10)과 방향별 검사로 구성한다.
- 국가 사이버보안 기본지침 제55조는 외부 발송 정보를 로그 항목에 넣고 로그를 1년 이상 보관하며 위·변조와 외부 유출을 막도록 한다(p.60).
- 원문 개인정보가 담긴 Vault 매핑은 요청 범위가 끝나거나 TTL이 지나면 지운다. 같은 지침 제66조 ⑤의 삭제 의무는 ②~④의 예외 처리 방법에만 걸리므로 근거로 삼지 않고, 원문을 필요한 동안만 두는 이 프로젝트의 설계로 둔다.
- 선택지가 늘면 기관의 설정 실수와 시험 조합이 함께 늘어난다.

## 보안 영향

- 기관이 잘못 고를 수 있는 보안 설정이 없다.
- 장애, 과부하, 탐지 실패 시 요청은 거절된다. 원문은 외부로 나가지 않는다.

## 변경 조건

- 기관 요구로 설정을 늘려야 하면 안전한 기본값을 유지하는 범위에서 항목별로 추가한다.
