# 0018. 탐지 텍스트 처리: 패턴 판정 방식과 정규화 라이브러리

상태: 확정 (2026-10-18)

## 결정

- 결정론 detector는 정규식 엔진을 쓰지 않는다. 패턴마다 직접 작성한 선형 스캐너로 판정하고, 단어 목록(문맥어, 표지어, 범주어, 기관 보호어)은 Aho-Corasick 사전 일치기로 찾는다.
- 각 스캐너는 입력을 앞에서부터 한 번 지나가고, 앞뒤를 보는 길이는 상수(예: 계좌 최대 34자리)로 묶는다. 백트래킹을 하지 않는다.
- 탐지용 보기의 NFKC 정규화(ADR 0007)는 utf8proc 2.12.0으로 한다. 결합이 넘지 않는 구간마다 정규화하고 각 결과 글자에 구간의 원문 byte 범위를 준다. 마지막에 전체 NFKC 결과와 비교해 다르면 탐지 실패로 보고 요청을 거절한다.
- detect 모듈도 core와 같은 금지 패턴 검사(I/O, 시계, 난수, `<regex>`, 가변 전역)를 받는다.

## 대안

| 대안 | 거절 이유 |
|---|---|
| `std::regex` | 표준 라이브러리 구현이 백트래킹 방식이라 처리 시간이 입력 길이에 비례한다는 보장이 없다. 긴 입력에서 재귀로 stack overflow가 난 보고가 있다. core 금지 패턴에도 걸린다 |
| RE2 | 처리 시간은 선형이지만 RE2(BSD-3)와 abseil(Apache-2.0) 두 의존성이 늘고, 탐지용 보기를 다시 UTF-8로 만들어 원문 위치와 이어야 한다. 메모리 한도 초과라는 새 실패 경로도 생긴다. 필요한 패턴에 정규식 일반성이 쓰이지 않아 이득이 작다 |
| NFKC 직접 구현 | Unicode 분해·조합 표 전체를 관리해야 하고 Unicode 판이 바뀔 때마다 따라가야 한다 |

## 근거

- 필요한 패턴은 세 가지뿐이다. 글자 종류 묶음과 짧은 고정 구조(숫자열, IBAN, 이메일, IP, 인코딩 덩어리), 고정 접두(키 접두, PEM 머리), 단어 목록. 셋 다 정규식 없이 선형 시간으로 판정할 수 있다.
- utf8proc 2.12.0은 MIT(Unicode data license 포함)이고 vcpkg 포트로 고정된다. Phase 2 실험에서 NFC·NFKC와 일반 범주 판정에 이미 썼다.
- 선형성은 fuzz 시간 제한(입력마다 5초)과 측정 도구의 최악 입력 시간 비율(64 KiB와 4 KiB의 처리 시간 비율 32 이하)로 확인한다.

## 보안 영향

- 공격자가 만든 입력으로 탐지 시간을 늘려 서비스를 멈추게 하는 방법(ReDoS)을 구조적으로 막는다.
- 정규화 결과가 어긋나면 탐지를 건너뛰지 않고 거절하므로, 정규화 문제가 우회 경로가 되지 않는다.
- utf8proc는 제품 배포물에 포함되므로 라이선스 고지 대상이다.

## 변경 조건

- 선형 스캐너로 표현하기 어려운 패턴이 반복해서 필요해지면 RE2 도입을 다시 검토한다.
- utf8proc를 올릴 때는 Unicode 판 변경에 따른 NFKC 차이를 시험으로 확인한다.
