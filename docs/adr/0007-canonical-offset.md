# 0007. 기준 offset과 정규화

상태: 확정 (2026-10-05)

## 결정

- 모듈 사이에서 주고받는 위치는 원문의 UTF-8 byte offset `[start, end)` 하나로 한다.
- 탐지는 원문이 아니라 탐지용 보기에서 한다. 만드는 순서는 UTF-8 엄격 검증, zero-width 문자(U+200B, U+200C, U+200D, U+2060, U+FEFF) 제거, NFKC 정규화다.
- 탐지용 보기의 각 코드포인트는 자신이 온 원문 byte 구간을 기억한다. 탐지 결과는 그 구간으로 되돌린다.
- 원문은 바꾸지 않는다.
- codepoint offset은 화면 표시용, token offset은 모델 내부용으로만 쓰고 타입을 구분한다.

## 대안

- 정규화된 문자열 기준 offset.
- codepoint offset.
- NFC 정규화.

## 근거

- 4개 모델 구성과 60개 fixture에서 offset 오류 0. 조합형으로 분리된 한글, zero-width 문자, BOM, 결합 문자, 이모지, 전각 문자를 포함했다.
- 조사 경계가 subword 안쪽에 있어 token 단위 offset으로는 경계를 표현할 수 없었다.
- NFKC는 NFC 대비 전각 문자로 쓴 조직명 1건을 더 찾았고 회귀는 없었다. 근거 사례가 적어 더 큰 셋에서 다시 확인한다.

## 보안 영향

- 전각 문자나 보이지 않는 문자를 끼워 넣어 탐지를 피하는 방법을 줄인다.
- 복원은 원문 byte를 그대로 쓰므로 정규화가 사용자 텍스트를 바꾸지 않는다.

## 변경 조건

- 더 큰 합성 셋에서 NFKC가 오탐을 늘리면 NFC로 되돌린다.
