# 0007. 기준 offset과 정규화

상태: 확정 (2026-10-05, 2026-11-03 보이지 않는 글자 범위와 LaTeX 보기를 더함, #234·결정 #235, 같은 날 줄 넘은 번호·사용자 정의 명령·Typst 를 더함, 결정 #238)

## 결정

- 모듈 사이에서 주고받는 위치는 원문의 UTF-8 byte offset `[start, end)` 하나로 한다.
- 탐지는 원문이 아니라 탐지용 보기에서 한다. 만드는 순서는 UTF-8 엄격 검증, 보이지 않는 글자 제거, NFKC 정규화다.
- 보이지 않는 글자는 서식 문자(Unicode Cf: zero-width, soft hyphen U+00AD, BOM, U+2063, U+180E 등), 탭·줄바꿈(CR, LF) 밖의 제어 문자(C0, DEL, C1), 비문자 U+FFFE·U+FFFF 다. 처음에는 zero-width 5개(U+200B, U+200C, U+200D, U+2060, U+FEFF)만 지웠는데, 나머지가 번호 사이에 끼면 탐지가 끊겼다(#234).
- 탐지용 보기의 각 코드포인트는 자신이 온 원문 byte 구간을 기억한다. 탐지 결과는 그 구간으로 되돌린다.
- 번호의 숫자 묶음 사이 구분자는 하이픈·대시류, 빈칸, 점, 탭이고 줄바꿈 밖으로 연속 3개까지다. 줄바꿈은 그 옆에 하이픈이 있을 때만("900101-" 줄바꿈 "1234567"), 번호마다 한 번 건넌다. 줄바꿈을 모두 받으면 표에서 줄마다 놓인 날짜·항목 번호가 주민등록번호·카드로 이어져 받은 문서 108개·공문서 231개의 새 탐지가 생겼다(#236).
- 숫자 사이에서 줄이 끊긴 번호(하이픈 없는 줄바꿈)는 따로 한 번 더 이어 보되, 줄을 넘는 번호는 그 종류의 단서 낱말(주민·생년월일·등록번호·외국인, 전화·연락·휴대·팩스·tel·phone, 카드·card, 사업자, 면허)이 앞 30글자 안에 있을 때만 받는다(결정 #238). 받은 문서·공문서에서 새 탐지 0.
- 글에 `\`, `$`, `{`, `}`, `#`, `[` 가 있으면 LaTeX·Typst 표기(영문 명령, `\,` 같은 띄움 명령, 중괄호, `$`, `%` 에서 줄 끝까지, Typst 의 `#이름`·`#[ ]`·`[ ]`)를 더 지운 두 번째 보기를 만들어 번호·이메일·IP 만 한 번 더 찾고, 찾은 원문 구간을 첫 보기 글자로 덮는다. 치환은 명령까지 포함한 원문 구간 전체를 덮는다. 계좌는 문맥어와 통화 기호(`$`)에 기대므로 두 번째 보기에서 찾지 않는다. `~` 는 한글 문서에서 기간 표시라 지우지 않는다.
- 두 번째 보기는 인자 없는 사용자 정의 명령(`\newcommand{\a}{…}`, `\def\a{…}`)의 정의를 지우고 쓴 자리에 내용을 넣는다. 내용은 ASCII 64자까지, 정의 256개까지, 한 단계만이며, 넣은 글자는 쓴 명령의 원문 구간을 가져 치환이 명령째 덮는다.
- 원문은 바꾸지 않는다.
- codepoint offset은 화면 표시용, token offset은 모델 내부용으로만 쓰고 타입을 구분한다.

## 대안

- 정규화된 문자열 기준 offset.
- codepoint offset.
- NFC 정규화.

## 근거

- 4개 모델 구성과 60개 fixture에서 offset 오류 0. 조합형으로 분리된 한글, zero-width 문자, BOM, 결합 문자, 이모지, 전각 문자를 포함했다.
- 조사 경계가 subword 안쪽에 있어 token 단위 offset으로는 경계를 표현할 수 없었다.
- NFKC는 NFC 대비 전각 문자로 쓴 조직명 1건을 더 찾았고 회귀는 없었다. 근거 사례가 적어 더 큰 셋에서 다시 확인한다.
- LaTeX 가 내는 수학 글자(𝟗 같은 U+1D400 블록)와 합자(ﬁ)도 NFKC 로 보통 글자가 된다. 수학 굵은 숫자로 쓴 주민등록번호를 찾는 것을 확인했다(#234).
- 두 번째 보기를 붙인 뒤 받은 문서 146개·공문서 160개에서 새 탐지는 각 3개(사업자등록번호 2, 전화 1, 모두 가명화 종류)였다(#236).

## 보안 영향

- 전각 문자나 보이지 않는 문자를 끼워 넣어 탐지를 피하는 방법을 줄인다. 채팅 글에 같은 문자를 넣는 우회도 함께 막는다.
- 막지 못하는 것: 인자가 있거나 다른 명령을 품은 LaTeX 매크로, 여러 단계로 펼쳐야 하는 매크로. 다 풀려면 TeX 를 실제로 돌려야 하고, TeX 실행은 외부 명령 실행 위험이 있어 하지 않는다. 단서 낱말 없이 숫자 사이에서 줄이 끊긴 번호, 그림 속 글자(글자 인식은 결정 #238 로 나중에 실험).
- 복원은 원문 byte를 그대로 쓰므로 정규화가 사용자 텍스트를 바꾸지 않는다.

## 변경 조건

- 더 큰 합성 셋에서 NFKC가 오탐을 늘리면 NFC로 되돌린다.
