# 0026. 짧은 수명 provider 자격 증명

상태: 확정 (2026-11-02)

## 결정

게이트웨이는 provider 로 보내기 직전에 자격 증명 파일을 요청마다 읽는다. 새 자격 증명을 받는 일은 게이트웨이 밖의 예약 작업이 하고, 그 값을 `prompt-airlock protect-credential - <파일>` 로 바꿔 끼우면 다음 요청부터 쓴다. 재기동은 필요 없다.

| 경우 | 동작 |
|---|---|
| 기동 | 파일을 한 번 읽어 보고, 못 읽으면 기동하지 않는다(설정 실수를 바로 알림) |
| 요청 | 보내기 직전에 파일을 읽어 `Authorization: Bearer` 에 쓴다 |
| 파일이 없음, 보호되지 않음, 비었음, 쓸 수 없는 글자 | 연결하지 않고 그 요청을 거절한다(provider 호출 0, `provider_unavailable`) |
| 갱신 | `protect-credential` 이 옆 임시 파일(`<파일>.tmp`, Linux 0600)에 다 쓴 뒤 이름을 바꿔 한 번에 갈아 끼운다 |
| 갈아 끼우는 순간 읽는 중이라 실패 | `protect-credential` 이 0 이 아닌 값으로 끝난다. 갱신 작업이 다시 시도한다 |

- 보호 방식은 ADR 0021 그대로다. Windows 는 DPAPI(현재 사용자), Linux 는 권한 0600. 그래서 갱신 작업은 게이트웨이와 같은 계정으로 돈다.
- `protect-credential` 의 입력 `-` 는 표준 입력이다. 갱신 작업이 평문 자격 증명을 디스크에 쓰지 않게 하려는 것이다.
- 고정 API 키도 같은 방식이다. 파일을 바꿔 끼우면 재기동 없이 바뀐다.

갱신 작업 예(Vertex, access token 수명 1시간)

```
# 30분마다, 게이트웨이와 같은 계정으로
gcloud auth print-access-token | prompt-airlock protect-credential - <설정의 credential_file>
```

## 근거

- Vertex 의 Chat Completions 호환 엔드포인트는 OAuth access token 으로 인증하고, 서비스 계정 access token 은 기본 1시간 산다. 공식 문서는 주기적으로 새로 받아 바꿔 넣으라고 안내한다(Vertex 의 Chat Completions 호환 인증 문서, 2026-11-02 확인).
- 파일 읽기와 DPAPI 풀기는 provider 왕복(수백 ms 이상)보다 훨씬 작다. 캐시와 변경 감지를 두지 않으면 바꿔 끼운 값이 언제 쓰이는지에 대한 경우의 수가 없다.
- 이름 바꾸기는 같은 폴더 안에서 한 번에 일어나므로, 읽는 쪽은 옛 파일 아니면 새 파일만 본다.

## 대안

| 대안 | 거절 이유 |
|---|---|
| 게이트웨이가 서비스 계정 비밀 키로 JWT 를 서명해 직접 access token 을 받음 | OpenSSL 사용 범위가 TLS 설정과 SHA-256 두 곳(ADR 0014)에서 RSA 서명까지 넓어진다. 1시간짜리 token 보다 오래 사는 비밀 키를 게이트웨이 호스트에 둬야 하고, Google 인증 서버로 나가는 연결이 하나 더 생긴다 |
| 1시간마다 재기동 | 재기동 동안 요청이 끊기고, 진행 중인 요청의 Vault 범위가 사라진다 |
| 파일 바뀜을 감지해 캐시를 갈아 끼움 | 감지 시점과 쓰는 시점 사이의 경우를 따로 다뤄야 한다. 요청마다 읽는 것보다 코드가 많고 얻는 시간은 작다 |
| 기한 없는 API 키(Vertex express mode) | 키 하나가 새면 기한 없이 쓰인다. 기관이 고르면 이 방식으로도 그대로 쓸 수 있다 |

## 보안 영향

- 게이트웨이 호스트에는 provider access token(1시간)만 있고, 서명용 비밀 키는 없다. 비밀 키는 갱신 작업을 도는 계정이나 기관의 키 관리 도구가 가진다.
- 갱신 작업이 멈추면 token 이 만료되어 provider 가 401 을 돌려주고 요청은 거절된다(평문으로 새지 않는다). 운영 감시는 provider 오류 비율로 한다.
- 자격 증명 값은 감사 기록에 남기지 않는다(ADR 0021).

## 변경 조건

- 기관이 게이트웨이 안에서 token 을 받기를 요구하면 ADR 0014 의 암호 사용 범위를 함께 다시 정한다.
