# 0013. 기관 분류 등급의 식별

상태: 확정 (2026-10-05)

## 결정

등급은 기관이 정한다. Gateway는 등급을 판정하거나 낮추지 않고, 요청마다 등급을 확인하고 내용을 검사한다.

1. 출처 등록: 기관은 Gateway를 쓰는 출처(시스템, 앱, 사용자 그룹)마다 인증 수단과 등급 정책 하나를 설정에 등록한다.
   - `o-only`: 기관이 공개(O) 업무정보만 처리하도록 분리한 시스템. 요청에 등급 표시가 없으면 O로 본다.
   - `declare`: 민감(S) 영역 단말에서 쓰는 앱처럼 여러 등급이 섞일 수 있는 출처. 요청마다 등급 표시가 있어야 한다.
   - 등록되지 않은 출처는 인증 단계에서 거절한다.
2. 등급 표시: HTTP 헤더 `X-Prompt-Airlock-Grade`, 값은 `C`, `S`, `O` 중 하나. 공식 문서에 공개·민감 등급의 표시 형식이 없어 이 프로젝트가 정한 형식이다. 값이 여러 개이거나 형식이 다르면 거절한다.
3. 처리 순서: 출처 인증 → 등급 확정(표시, 또는 `o-only`의 기본값) → C, S, 알 수 없음이면 차단 → O면 내용 검사(형식 있는 값 detector, 한국어 이름·조직 탐지, 기관 보호어, 잔여 검사) → 통과한 요청만 외부로 보낸다.
4. 내용 검사는 등급과 상관없이 항상 한다. 등급이 O여도 검사에서 걸리면 가명화하거나 차단한다.
5. 요청마다 출처, 등급의 출처(표시 또는 출처 기본값), 판정 결과와 차단 사유 코드를 감사 메타데이터로 남긴다.

## 대안

| 대안 | 거절 이유 |
|---|---|
| Gateway 전체를 O 전용으로 선언하고 요청 표시를 받지 않음 | 업무 단말이 민감(S) 등급인 환경에서 요청별 등급 확인을 하지 않게 된다 |
| 요청 표시를 받되 없으면 O로 봄 | 식별되지 않은 요청이 통과한다 |
| 모든 요청에 표시 필수 | 기관이 O 전용으로 분리한 시스템까지 앱을 고쳐야 한다 |

## 근거

공식 문서 7종을 원문으로 확인했다(국가사이버안보센터 게시본, SHA-256 대조). 쪽은 인쇄 쪽이다.

| 확인한 내용 | 근거 |
|---|---|
| 등급 분류는 각급기관의 장이 업무기능 단위로 한다 | 국가 사이버보안 기본지침 제39조의2(p.44), N2SF 이해 및 활용 안내 p.5~6 |
| 업무정보 등급을 정한 뒤 정보시스템 등급을 정하고, 등급별 시스템 분리가 원칙상 가장 명확하다 | N2SF 보안 가이드라인 1.0 본문 p.40~43, 기본지침 제39조의3·4 |
| 표시 양식이 규정된 것은 비밀뿐이며 공개·민감 등급의 표시 형식은 없다 | 기본지침 제64조(p.67) |
| 외부 언어모델 서비스에 쓰는 업무정보는 O로 한정한다 | 부록 2-2 정보서비스 모델 2 p.11, 국가ㆍ공공기관 보안 가이드북 p.107 |
| 상용 서비스로 기밀·민감 업무정보를 작성·저장·수발신하지 않는다 | 기본지침 제66조 ④(p.70) |
| 연계체계는 등급 식별과 프롬프트·콘텐츠 필터링으로 O 외 정보 유출을 막는다 | 부록 2-2 p.24 ③ |
| 등급에 따른 흐름 차단(IF-14), 등급 표시·메타데이터 기반 전달(CD-2, CD-7), 비인가 정보 검사(IF-8) | 부록1 보안통제 항목 해설서 p.64, p.70 |
| 출발지 식별·인증(IF-9), 사용자·단말 사전 등록(CD-12), 승인된 목적·사용자로 교환 한정(CD-M3) | 부록1 p.64~65, p.71 |
| 교환 대상이 식별되지 않으면 정보교환을 중단(DT-2), 기본 차단 후 필요한 것만 허용(EB-3) | 부록1 p.87, p.66 |

"표시가 없으면 차단"은 공식 문서에 직접 쓰인 기본값이 아니다. 위 통제들의 취지에 맞춘 이 프로젝트의 정책이며, 기본 허용을 지지하는 근거는 찾지 못했다.

## 보안 영향

- 등급을 아무도 정하지 않은 요청은 외부로 나가지 않는다.
- 등급 표시는 사용자나 앱의 선언이므로 잘못 붙일 수 있다. 그래서 내용 검사를 항상 함께 한다.
- 등급 확인과 판정 결과가 모두 기록되어 사후에 확인할 수 있다.

## 편의성

- O 전용으로 분리한 시스템은 `o-only`로 등록하면 앱을 고치지 않고 쓴다.
- 여러 등급이 섞이는 단말의 앱만 헤더 하나를 붙인다. 사용자가 O 업무임을 확인하는 화면은 기관 앱의 몫이다.
- 기관 설정은 기존 "허용 사용자"를 "허용 출처(인증 수단과 등급 정책)"로 바꾼 것이라 항목 수는 늘지 않는다.

## 변경 조건

- 공식 문서에 공개·민감 등급의 표시 형식이 생기면 그 형식을 따른다.
- 기관의 분류 체계(문서 표시, 메타데이터)와 직접 연동해야 하면 등급 확정 단계에 그 연동을 추가한다.
