# 0030. 로컬 provider 자격 증명 교체

상태: 확정 (2026-11-20, #273)

## 결정

- `POST /v1/provider/credential`은 로컬 콘솔에서 현재 provider 자격 증명 파일을 교체한다. `provider.credential_rotation_origin`이 없으면 비활성이고, 값은 `origins`에 이미 등록된 이름 하나여야 한다.
- 요청은 해당 출처의 기존 token과 O 등급을 통과해야 한다. 접속 주소는 `127.0.0.1`, Host는 현재 게이트웨이의 로컬 주소, 브라우저 Origin은 있으면 같은 HTTPS 출처여야 한다. 중복 헤더는 거절한다.
- 본문은 4 KiB 이하의 JSON 객체 `{"credential":"..."}` 하나다. 추가·중복 키, 빈 값, 인쇄 가능한 ASCII 이외 값은 거절한다. 경로는 본문에서 받지 않고 설정의 `provider.credential_file`만 사용한다.
- 저장 전에 원문 없는 `credential_rotation` 감사 이벤트를 쓴다. 감사나 입력 검증이 실패하면 저장 함수를 부르지 않는다. 응답은 성공 여부와 고정 오류 코드만 담는다.
- HTTP 입구와 `protect-credential`은 같은 `store_credential`을 쓴다. 저장 함수는 프로세스 ID와 증가 번호가 포함된 새 임시 파일을 배타적으로 만들고, Windows DPAPI 결과 또는 Linux 0600 파일만 기록한 뒤 같은 디렉터리에서 원자적으로 교체한다. 실패 시 기존 파일을 먼저 지우지 않으며 임시 파일을 정리한다.
- 요청별 파일 재읽기와 기동 시 자격 증명 검증은 ADR 0026대로 유지한다. HTTP 교체는 provider 호출이나 재시도를 하지 않는다.

## 예외와 영향

ADR 0021의 네트워크 관리 입구 금지에 대한 좁은 예외다. 읽기·검증·내보내기나 일반 출처에 파일 쓰기 권한을 더하지 않는다. 기존 token 검증과 공개 등급 판정, DPAPI/0600 보호를 재사용하며 OpenSSL 호출 범위는 바꾸지 않는다.

## 대안

| 대안 | 이유 |
|---|---|
| 모든 등록 출처에 교체 허용 | 대화 출처에 파일 교체 권한까지 주게 된다 |
| 요청 본문에서 저장 경로 받기 | 임의 파일 쓰기 경계가 생긴다 |
| 임시 파일 하나를 공용으로 사용 | CLI와 HTTP의 동시 갱신이 서로의 내용을 덮을 수 있다 |
