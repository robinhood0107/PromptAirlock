# 0022. 문장 단위 민감정보 판별기

상태: 확정 (2026-10-30)

## 결정

공개 모델을 학습 없이 쓰는 문장 판별기는 지금 채택하지 않는다. 민감정보는 단어 규칙(범주어와 개인 표지, ADR 0016)과 감사 기록을 그대로 쓴다.

- 판정은 미리 정한 통과 수치로 했다(결정 #147). 가장 좋은 구성이 재현율과 지연은 통과했지만, 판정용 셋에서 통과해야 하는 문장을 11.3% 잘못 막아 기준(5.5% 이하)을 넘었다.
- 측정 도구, 합성 셋, 예시 문장 데이터는 남긴다. 기본 빌드에는 들어가지 않고 vcpkg 기능 `sentence-spike` 를 켠 구성에서만 만든다.
- 판정용 셋을 본 뒤에는 그 셋으로 문턱값이나 예시 문장을 다시 고르지 않는다. 다시 재려면 새 판정용 셋을 만든다.

## 판정

구성: `intfloat/multilingual-e5-small`(커밋 `614241f6`), 글을 문장 하나씩 나눠 판정, 개인 표지가 있는 글에서만 판별기 결과 사용, 범주별 예시 문장 상위 3개 유사도 평균에서 업무·일반 지식 예시와의 최대 유사도를 뺀 점수, 문턱값 0.0128(개발용 셋에서 고름). 규칙과 합쳐 둘 중 하나라도 걸리면 차단.

| 항목 | 통과 수치 | 개발용 셋 | 판정용 셋 | 판정 |
|---|---|---|---|---|
| 돌려 말함 재현율 | 60% 이상 | 67.3% | 68.9% (91/132) | 통과 |
| 문장 나눔 재현율 | 70% 이상 | 81.8% | 90.9% (30/33) | 통과 |
| 오차단 | 5.5% 이하 | 5.2% | 11.3% (108/957) | 실패 |
| 256 token 판별 시간 p95 | 150 ms 이하 | 113.919 ms | 101.073 ms | 통과 |
| 메모리 증가 | 700 MB 이하 | +662 MB | +662 MB | 통과 |

- 규칙만으로는 판정용 셋의 돌려 말한 문장을 0/132, 문장 나눔을 4/33 막았다.
- 잘못 막은 108건 가운데 82건이 사람 이름이 든 업무 문장(NER 판정용 셋 300개 중 27.3%)이었다. 개발용 셋의 같은 종류 문장에서는 수 % 였다. 문턱값과 예시 문장을 개발용 셋으로 고른 만큼 처음 보는 문장 모양에서 흔들린 것으로 읽힌다.

## 대안

| 대안 | 거절 이유 |
|---|---|
| e5-small 구성을 오차단을 감수하고 채택 | 업무 문장 열 개 중 하나를 막으면 사용자가 우회 표현을 찾게 되어 차단의 뜻이 약해진다 |
| 문장 함의(zero-shot) 모델 | 개발용 셋에서 돌려 말함을 가장 많이 잡았지만(65.5%) 256 token 문장 하나에 p95 7.29초, 일반 지식 문장 오차단 42.4% |
| e5-base, paraphrase-multilingual-MiniLM | 개발용 셋에서 e5-small 보다 낮거나 느렸다(#152) |
| 판정용 셋 결과를 보고 문턱값을 다시 고름 | 판정용 셋이 개발용 셋이 되어 수치가 부풀고, 처음 보는 문장에서의 성능을 알 수 없게 된다 |
| 작은 분류기를 학습 | 학습하지 않기로 정했다(결정 #147). 학습하면 보안 가이드북의 학습 관련 항목과 학습 데이터 관리가 따라온다 |

## 근거

- 결정 #147(범위, 학습 없음, 통과 수치), 측정 #149(규칙 기준선), #152(후보 3개, 개선 단계), #153(판정용 셋 판정).
- 보안 가이드북은 문장 단위로 이해하는 기능이 없으면 단어 기반 필터를 임시로 쓰되 로깅·모니터링하도록 한다(FAQ Q5). 지금 감사 기록은 범주어가 있었으나 통과한 문장의 범주와 건수를 남긴다(ADR 0016).

## 보안 영향

- 범주어 없이 돌려 말한 민감정보는 지금도 막지 못한다(판정용 셋 0/132). 띄어쓰기·보이지 않는 문자·자모 분리 같은 글자 변형은 규칙이 막는다(판정용 셋 64/66, 놓친 2건은 인증 정보 표지어와 값 사이에 다른 말이 낀 모양).
- 기밀(C)·민감(S) 등급 요청은 내용과 상관없이 외부로 보내지 않으므로(ADR 0013), 이 빈틈은 공개(O) 등급으로 들어온 요청에 해당한다.

## 변경 조건

다음 가운데 하나가 생기면 새 판정용 셋으로 다시 판정한다. 로드맵 재계획(Phase 11 앞, 결정 #147)에서 함께 정한다.

- 학습을 허용하거나, 기관별 예시 문장을 운영 중에 더하는 방식으로 범위를 바꿀 때
- 실제 문서 평가 틀이 생겨 합성 문장보다 실제에 가까운 셋으로 잴 수 있을 때
- 처리 시간·메모리 예산이 바뀌거나(GPU, 더 큰 모델), 개인 표지 판정이 나아질 때
