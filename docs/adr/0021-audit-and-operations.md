# 0021. 감사 기록과 운영

상태: 확정 (2026-10-22)

## 결정

감사 기록 형식(G16, G20)

- 로컬 파일 JSON lines. 줄마다 스키마 판 `v`(지금 1), UTC 시각, 이벤트 종류, 심각도를 둔다.
- 요청 이벤트 필드: 요청 ID, 출처 이름, 접속 주소, 인증 결과, 등급, 결과(통과·거절), 사유 코드, 차단 종류, 탐지 종류별 건수, 처리 시간.
- 관리 이벤트: 기동(설정 파일 SHA-256 포함), 종료, 만료 삭제, CLI 열람·검증·내보내기.
- 원문, 대응(mapping), 자격 증명, 응답 본문은 감사 기록에 넣지 않는다.

외부 전송 이력(G14, G21)

- 외부로 실제 보낸 가명 상태의 요청 본문과 복원 전 provider 응답을 같은 감사 폴더의 이력 파일에 남긴다. 복원한 원문은 남기지 않는다.
- 거절된 요청은 본문을 남기지 않고 메타데이터만 남긴다. 관리자 검토도 메타데이터로만 한다(G21 (a)).
- 보존 기간은 설정 `history_retention_days`(365 이상, 기본 365)이다. 1년 보관 근거는 국가정보원 보안업무 지침 제55조와 N2SF DU-M3 이다.

변조 탐지와 만료 삭제(G19)

- 하루 단위 세그먼트 파일. 각 줄은 앞 줄의 SHA-256 을 담아 연결하고, 세그먼트 첫 줄은 앞 세그먼트 마지막 해시를 이어받는다.
- 세그먼트를 닫을 때 마지막 해시와 줄 수를 checkpoint 파일에 적는다. 끝부분을 잘라내거나 통째로 바꾸면 checkpoint 와 맞지 않는다.
- 만료 삭제는 세그먼트 단위로 하고, 지운 세그먼트의 마지막 해시를 삭제 이벤트로 남겨 이후 연결을 검증할 수 있게 한다.

운영 기능(G18, G22, G23)

- 네트워크 관리 endpoint 를 두지 않는다. 열람·검증·내보내기는 서버 로컬 CLI(`prompt-airlock audit ...`)로만 한다.
- 설정 변경은 재기동으로 반영하고, 기동 이벤트에 설정 파일 해시를 남긴다.
- provider 자격 증명: Windows 는 DPAPI(현재 사용자)로 보호한 파일, Linux 는 권한 0600 파일만 읽는다. 교체는 파일을 바꾸고 재기동한다. provider 오류 본문은 버린다(ADR 0017).
- TLS 설정 항목은 수신 인증서·키와 provider 신뢰 저장소로 한정한다. 수신 인증서 만료 30일 전부터 기동 때 경고 이벤트를 남긴다. 폐지 확인은 하지 않는다.

응답 능동 콘텐츠(G7)

- 응답에 `<script`, `javascript:`, `vbscript:` 가 있으면 응답을 거절한다(사유 `response_active_content`).
- 악성코드 검사는 Gateway 가 하지 않는다. 필요하면 provider 주소를 DMZ 중계·검사 장치로 둔다.

## 대안

| 대안 | 거절 이유 |
|---|---|
| 차단 본문 짧은 기간 격리 보관(G21 b) | 차단된 원문을 별도로 보관하는 위험이 검토 이득보다 크다 |
| 외부 수집 시스템(SIEM)으로 직접 전송 | 감사 기록은 S 등급, 로컬 파일만 허용(불변식) |
| 네트워크 관리 API | 공격면이 늘어난다 |

## 보안 영향

- 감사·이력 파일은 원문 대응을 담지 않지만 가명 상태 질문과 응답을 담으므로 S 등급 보호 대상이다.
- 연결 해시는 무결성 확인용이며 비밀 키가 없으므로 파일 전체를 다시 계산해 바꾸는 공격은 checkpoint 를 별도 보관해야 막을 수 있다.

## 변경 조건

- 기관 SIEM 연동 요구가 생기면 로컬 파일 수집 방식으로만 검토한다.
