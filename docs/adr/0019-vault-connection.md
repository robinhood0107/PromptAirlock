# 0019. Vault 연결: 요청 단위 매핑, 장애 재시작, 메모리 잔류

상태: 확정 (2026-10-18)

## 결정

매핑 범위

- 가명 매핑은 요청 단위다. Gateway는 요청 하나마다 Vault 범위(scope)를 하나 열고, 요청 처리가 끝나면(복원까지 마친 뒤) 범위를 지운다. TTL은 범위가 남는 상한일 뿐이다.
- 다중 턴 대화는 매 요청에서 모든 역할의 메시지를 다시 탐지하고 가명화한다. 이전 응답에서 복원된 원문이 다음 요청에 들어와도 그 요청의 범위에서 새로 가명화된다.

연결과 장애

- Gateway는 Vault를 자식 프로세스로 띄우고 READY 한 줄에서 끝점과 비밀값을 받는다(ADR 0003). 연결은 유한한 풀(기본 8개)로 관리하고, 연산 하나 동안만 연결을 빌린다. 빌리는 대기 시간을 넘으면 과부하로 보고 요청을 거절한다.
- 연결 오류, 시간 초과, 프로토콜 오류가 나면 그 연결은 다시 쓰지 않는다.
- Vault 프로세스가 끝나거나 연결이 모두 끊기면 그 세대(generation)를 죽은 것으로 표시한다. 진행 중 요청과 그 세대의 범위가 필요한 응답 복원은 거절한다. 다음 요청 때 새 비밀값으로 Vault를 다시 띄운다. 재시작 간격은 1초에서 시작해 연속 실패마다 두 배, 최대 30초다. 그 사이 요청은 모두 거절한다.
- 클라이언트는 연결할 때 서버 pid가 자신이 띄운 프로세스인지 확인한다(Windows `GetNamedPipeServerProcessId`, Linux `SO_PEERCRED`). 서버는 Windows DACL과 Linux 소켓 권한·uid로 접근을 막는다.

오류 대응

core 발급·복원 인터페이스는 core 오류만 돌려주므로 클라이언트가 Vault 오류를 바꾼다. 원래 원인은 감사용으로 따로 보관한다.

| Vault·전송 결과 | 발급 | 복원 |
|---|---|---|
| TOKEN_NOT_FOUND, MALFORMED_TOKEN | - | token 없음(응답 복원 거절) |
| 범위 없음·만료, 세대 종료 | 발급 불가 | 복원 불가 |
| OVERLOADED, SHUTTING_DOWN, 시간 초과, 연결 오류, 풀 대기 초과 | 발급 불가 | 복원 불가 |
| 값·매핑·범위 한도, 잘못된 인자 | 발급 불가 | 복원 불가 |
| 버전·형식·인증 오류, INTERNAL | 발급 불가(연결 폐기) | 복원 불가(연결 폐기) |

사용자에게는 core 사유 코드(보호 불가, 응답 token 미복원)만 간다.

메모리 잔류

- Vault는 해제하는 모든 메모리를 0으로 지우는 전역 할당기를 쓴다. 재할당할 때는 새 영역에 복사한 뒤 옛 영역을 지우고 해제한다. Windows Named Pipe 경로의 통신 라이브러리 내부 버퍼, 컬렉션 재할당 잔류, 디코딩 임시 버퍼가 함께 지워진다.
- C++ 클라이언트는 복원 값을 담은 protobuf 필드를 값을 옮긴 뒤 지운다.

묶음 복원

- Phase 6에서는 v1 연산 네 가지만 쓴다. 측정에서 token 64개 복원 p95가 10 ms를 넘으면 묶음 복원(v2)을 따로 제안한다.

사용하는 라이브러리

- C++ 클라이언트의 통신은 Boost.Asio 1.92(ADR 0004에서 고른 판), 직렬화는 libprotobuf(vcpkg protobuf). Rust Vault는 prost.

## 대안

| 대안 | 거절 이유 |
|---|---|
| 세션 단위 매핑 | 외부 언어모델은 요청마다 기억이 없어 이득이 작고, 원문 보관 시간이 늘며, 믿을 수 없는 세션 식별자와 만료 설계가 필요하다. Vault 재시작 때 세션 전체를 잃는다 |
| Vault 장애 시 Gateway 중단 | 가장 단순하지만 일시 장애에도 운영자 개입이 필요하다 |
| 파이프 버퍼만 직접 overlapped I/O 로 지움 | unsafe 코드와 작업량이 크고, 재할당 잔류는 남는다 |
| 메모리 잔류를 기록만 하고 받아들임 | 원문 조각이 해제된 메모리에 남는다 |
| 처음부터 묶음 복원 | 필요한지 측정 전에는 알 수 없고, proto 버전을 올려야 한다 |

## 근거

- 요청 단위와 세션 단위 비교, 메모리 잔류 조사(Windows mio 파이프 내부 버퍼, Linux UDS 는 사용자 공간 중간 버퍼 없음, 공통 재할당 잔류)는 결정 이슈에 정리했다.
- Phase 3 실험의 측정: Named Pipe CreateToken p50 54.8 µs, p95 74.1 µs(ADR 0003).
- core 의 4자 누설 규칙과 Vault token 생성 규칙이 같다(ADR 0008).

## 보안 영향

- 원문은 요청 처리 동안만 Vault 메모리에 있고, 해제되는 메모리는 지워진다.
- 장애 중에는 가명화·복원이 모두 거절되므로 원문이 외부로 나가거나 잘못 복원되는 경로가 없다.
- 남는 한계: 커널 통신 버퍼, CPU 레지스터, 스택, 스왑된 페이지, 프로세스가 강제 종료될 때의 메모리는 지울 수 없다.
- 지우는 할당기는 해제마다 비용이 든다. 측정으로 확인한다.

## 변경 조건

- 측정에서 복원 지연이 기준을 넘으면 묶음 복원을 결정한다.
- 세션 단위가 필요한 요구(예: 외부 서비스의 대화 기억 기능)가 생기면 다시 정한다.
- 지우는 할당기 비용이 받아들일 수 없을 만큼 크면 다시 정한다.
