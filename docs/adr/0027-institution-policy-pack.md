# 0027. 기관 정책 묶음과 기관 번호

상태: 확정 (2026-11-02, 같은 날 기밀 문장 규칙을 더함)

## 결정

게이트웨이 설정에 기관 정책 묶음(`policy` 절)을 둔다. 기관은 업종을 고르고, 자기 표지어와 형식 마스크를 더한다. 표지어 뒤 번호와 마스크로 찾은 값은 새 종류 `INSTITUTION_ID` 이고 가명화한다. 기밀 표지어와 업종 대상어가 같은 창에 있는 문장은 새 종류 `CONFIDENTIAL_MATTER` 이고 차단한다. 처리는 고정이다(ADR 0015). 종류는 19개가 된다.

```json
"policy": {
  "industries": ["hospital", "bank"],
  "id_labels": ["학번"],
  "id_formats": ["HR-####-###"],
  "confidential_markers": ["사내비"],
  "confidential_subjects": ["한빛 프로젝트"]
}
```

| 항목 | 내용 | 상한 |
|---|---|---|
| `industries` | 업종 이름. `public-admin`, `public-enterprise`, `hospital`, `human-resources`, `bank`, `card`, `insurance` 은 표지어가 있고, `defense`, `legal`, `school`, `telecom`, `research`, `police` 는 이름만 받는다 | 13개, 중복 거부 |
| `id_labels` | 기관이 더하는 표지어 | 256개, 각 32자 |
| `id_formats` | 형식 마스크 | 16개, 각 40자 |
| `confidential_markers` | 기관이 더하는 기밀 표지어 | 256개, 각 32자 |
| `confidential_subjects` | 기관이 더하는 기밀 대상어 | 256개, 각 32자 |

표지어 뒤 번호
- 표지어(업종 + 기관) 다음에 구분이 오고 번호가 오면 번호를 `INSTITUTION_ID` 로 본다.
- 구분: `:` `=` `#` `(`, 표지어에 바로 붙은 은/는/이/가, 또는 공백. 표지어가 다른 글자에 바로 붙어 있으면(사번호) 보지 않는다.
- 번호: 영문·숫자·`-`·`/` 로 4~30자, 숫자 3개 이상, 영문이나 숫자로 시작. 30자를 넘거나 `_` 가 이어지면 번호가 아니다. 하이픈 바로 뒤에 공백이 3개까지 끼고 영문·숫자가 이어지면 한 번호로 본다(공문서 160개 측정 #221 에서 번호 4개가 이 꼴로 잘렸다).
- 표지어 바로 앞이 한글이면 더 긴 말의 일부로 보고 건너뛴다(검사번호 안의 사번).

형식 마스크
- `#` 숫자, `@` 영문, `*` 숫자나 영문, 나머지 글자는 그대로(영문은 대소문자 무시). NFKC 뒤에 비교하므로 전각 글자도 같다.
- 자리 글자 4개 이상, 그대로 쓰는 글자 1개 이상. 공백·제어 문자는 받지 않는다. `####` 처럼 모든 4자리 숫자를 잡는 마스크는 거부한다.
- 찾은 값 앞뒤 글자가 영문·숫자·`_` 이면 버린다.

기밀 문장
- 기밀 표지어(대외비, 비공개, 미공개, 내부 검토용, 극비, Confidential 등 20개, 업종 공통)와 대상어(업종별 5~10개 + 기관 대상어)가 같은 문장에 있거나 이웃 두 문장에 하나씩 있으면 그 문장(들)을 막는다. 창은 민감정보 규칙(ADR 0016)과 같은 코드를 쓴다.
- 한쪽만 있으면 막지 않는다. 대상어가 하나도 없으면(업종을 고르지 않았고 기관 대상어도 없음) 규칙이 꺼진다.
- 업종 대상어는 지자체·행정 10, 공기업 7, 병원 5, 인사·노무 8, 은행 9, 카드 5, 보험 6개다.

설정이 틀리면(모르는 업종, 빈 값, 상한 초과, 마스크 문법 오류) 기동하지 않는다. 설정 해시는 지금처럼 감사 기록 `start` 에 남는다.

## 근거

- 기관 안에서 새면 곤란한 번호(차트번호, 사번, 여신번호)는 나라 공통 형식이 없어 기존 17종이 못 잡는다. 번호 이름이 바로 앞에 붙는 경우가 많으므로 표지어 뒤 값으로 잡고, 이름 없이 쓰는 기관 고유 형식은 기관이 마스크로 알려 준다.
- 정규식 대신 마스크를 쓴다. 기관이 정규식을 잘못 쓰면 되돌림 때문에 처리 시간이 폭발할 수 있다(ReDoS). 마스크는 위치마다 마스크 길이만큼만 비교하므로 글 64 KiB x 40자 x 16개로 묶인다.
- 경계에 `_` 를 넣는다. 가명 token 의 무작위 10글자는 늘 `_` 뒤에 있다(ADR 0008). 마스크가 token 안 글자를 잡으면 잔여 검사가 요청을 막는다.
- 가명화로 둔다. 번호는 사람이나 건을 가리키지만 모델 답에서 다시 쓰여야 쓸모가 있다. 잘못 잡아도 가명이 될 뿐 요청이 막히지 않는다.
- 민감정보 규칙(ADR 0016)의 개인 표지에 `INSTITUTION_ID` 를 넣는다. "차트번호 20231234 환자 우울증 진단" 은 특정 개인의 건강 정보다.
- 기밀 문장은 표지어와 대상어가 함께 있을 때만 막는다. "기밀" 한 단어로 막으면 보안 교육·규정 안내 같은 일반 문장이 막힌다. 합성 개발용 셋(#218)에서 표지어만 126, 대상어만 126, 문장 하나 건넌 것 42 모두 통과, 함께 있는 것 252/252 차단이었다.
- 기밀 문장은 차단한다. 가명으로 바꿀 값이 따로 없는 문장 전체의 뜻이 기밀이기 때문이다.
- 계좌·카드·주민등록·사업자등록 번호 표지어는 넣지 않는다. 이미 차단 종류가 따로 잡고, 겹치면 더 엄격한 처리가 이긴다.

## 대안

| 대안 | 거절 이유 |
|---|---|
| 기관이 정규식을 씀 | ReDoS 위험, 기관 운영자가 검증하기 어렵다 |
| 종류별 처리(가명화·차단)를 기관이 고름 | 고정 처리표(ADR 0015)가 깨지고, 설정 실수 하나로 차단 종류가 가명으로 나갈 수 있다. 판매 뒤 요구를 보고 다시 정한다 |
| 업종 표지어를 늘 켬 | 병원 아닌 곳에서 "접수번호" 같은 말까지 잡아 가명이 늘어난다. 업종을 고를 때만 켠다 |
| 기관 보호어(`internal_terms`)를 `policy` 안으로 옮김 | 이미 쓰는 설정이 깨진다. 자리만 다를 뿐 같은 일을 한다 |

## 보안 영향

- 기관 번호 원문은 provider 로 나가지 않는다. 같은 요청 범위 안에서만 복원한다(ADR 0008).
- 탐지 시간은 마스크 상한으로 묶인다. 표지어는 기존 단어 일치기(Aho-Corasick)를 써서 글 길이에 비례한다.
- 기밀 문장은 사전에 있는 대상어로만 잡는다. 대상을 바꿔 말하면 못 잡는다(#218 의 바꿔 말한 문장 0/42). 판별기는 미채택이다(ADR 0025).
- 공개 공공 문서 160개(#221)에서 기밀 문장으로 막힌 문서는 2개(1.2%)였고 둘 다 "비공개" 가 분류 표기·발언으로 쓰인 오차단이었다. 기관 번호 281개는 모두 실제 신청·접수번호였다.
- 업종 표지어는 공공·금융만 있다. 다른 업종을 골라도 표지어는 켜지지 않으니, 그 업종 기관은 `id_labels` 와 `id_formats` 로 채워야 한다.

## 변경 조건

- 공문서 측정(Phase 11-3)에서 기밀 문장 오차단이나 업종 표지어 오가명이 높으면 표지어를 줄이거나 구분 규칙을 좁힌다.
- 기관이 종류별 처리 변경을 요구하면 ADR 0015 와 함께 다시 정한다.
