# 미리보기와 로컬 확인

내장 `/console`은 미리보기, 파일 검사, 연결 설정, 접속 상태, 승인 목록과 관리자 조회를 제공합니다. 이 문서는 미리보기 API와 기존 로컬 확인 경계의 동작을 설명합니다.

## 미리보기

`POST /v1/preview`에 대화와 같은 본문·출처 token·등급 헤더를 보냅니다. 입력 필드와 한도도 대화 요청과 같습니다.

정상 결과는 `decision`이 `pass` 또는 `pseudonymized`이며, `outbound`에 보호 검사를 통과한 전송 예정 내용이 들어갑니다. `entities`는 종류별 건수, `documents`는 원문이나 제목을 제외한 문서 처리 통계입니다. 차단·확인이 필요한 요청은 기존 사유 코드와 상태를 반환합니다.

미리보기는 제공자를 호출하지 않고 실제 전송 이력도 쓰지 않습니다. 가명 범위는 응답 전에 정리합니다. 실제 전송은 보호 검사를 다시 하며 새 범위를 쓰므로 가명 문자열이 미리보기와 다를 수 있습니다.

## 채팅 앱 호환 모드

설정 파일에 다음 항목을 더합니다. 생략하면 기존 409 확인 흐름을 유지합니다.

```json
{
  "compat": { "chat_app": true }
}
```

이 모드에서는 게이트웨이를 127.0.0.1 또는 0.0.0.0에 바인딩해야 로컬 승인 주소로 연결할 수 있습니다. 콘솔 접근 자체는 127.0.0.1로 제한합니다.

- 차단·확인 안내는 게이트웨이가 생성한 대화 응답으로 반환하고, `prompt_airlock.decision`에 `blocked` 또는 `confirmation_required`를 명시합니다.
- 확인 안내의 링크는 게이트웨이를 실행한 PC의 HTTPS 로컬 주소입니다. 원래 채팅 앱에서 내용을 확인한 뒤, 공개(O)로 분류된 요청일 때만 승인합니다.
- 로그인에는 게이트웨이의 출처 token을 사용합니다. 외부 제공자의 API 키를 넣지 않습니다. 입력값은 브라우저 저장소나 URL에 보관하지 않습니다.
- 승인 후 원래 앱에서 같은 요청을 다시 생성합니다. 본문 바이트나 인증 출처가 다르면 승인되지 않으며, 한 번 사용하거나 처음 확인 요청부터 5분이 지나면 사용할 수 없습니다.
- 승인 페이지는 원래 요청을 저장하거나 외부 전송을 시작하지 않습니다. 원래 앱의 재시도에서 모든 보호 단계를 다시 거칩니다.
- 차단된 요청에는 승인 링크가 없습니다. 인증·입력·제공자 오류는 기존 오류 상태를 유지합니다.

HTTP 오류를 대화 안내로 바꾼 경우에도, 읽지 않은 본문이 남을 수 있는 연결은 닫습니다.

## 승인 API

`POST /v1/confirmations/approve`는 출처 인증과 공개 등급 확인을 적용하며, 접속 주소·Host·브라우저 Origin이 같은 로컬 게이트웨이여야 합니다. 본문은 1 KiB 이하의 `{"token":"확인 표지"}` 하나만 받습니다. 다른 키·중복 키·확인 헤더와의 중복 사용은 거절합니다.

승인 전 감사·취소·시간 검사를 통과해야 장부 상태가 바뀝니다. 장부는 원문 없이 본문 SHA-256·인증 출처·만료·승인 상태만 보관합니다. 승인 자체는 제공자·탐지기·Vault를 호출하지 않습니다.

기존 `X-Prompt-Airlock-Confirm` 헤더 방식도 사용할 수 있습니다. 헤더에 틀린 표지를 보낸 요청을 승인 장부로 우회하지 않습니다. 두 방식이 동시에 같은 승인을 사용하려 해도 한 요청만 사용할 수 있습니다.

설계 계약은 [ADR 0029](adr/0029-local-console-and-chat-app.md)에 있습니다.

## 로컬 감사 통계

서버의 감사 폴더를 지정해 전체 연결 무결성을 확인하고 최근 24시간의 요청 결과를 집계합니다.

~~~text
prompt-airlock stats <audit-dir>
~~~

정상, 정책 차단, 확인 필요, 그 밖의 실패는 최종 request 이벤트만 집계합니다. 차단은 등급·대상·인코딩·잔여 검사 사유이며, 그 밖의 거절은 실패로 셉니다. 확인 승인·미리보기·egress·응답 기록은 별도 요청으로 더하지 않습니다. 정상 결과는 scope=recent_24h와 coverage=complete를 표시합니다. 폴더가 없거나 비어 있으면 상태를 구분해 알리고, 손상·잘림은 고정 stage/code와 0이 아닌 종료값으로 실패합니다. 최근 구간이 제한되면 state=partial로 표시하고 부분 숫자를 성공 결과처럼 내보내지 않습니다. 이 명령은 감사 파일을 쓰거나 provider·Vault를 호출하지 않습니다.
